# Security

## What this repository protects against

A review tool reads files written by other people. Here those are model checkpoints from a public hub and a public repository of logs. Both are treated as untrusted data, however reputable their source. The design assumes that either could be altered between the day it was published and the day you download it.

| Risk | What the code does about it |
|---|---|
| A checkpoint that executes code when it is loaded | Weights are read from safetensors files only. The one place that loads a model passes `use_safetensors=True` and `local_files_only=True`, so a pickle in the folder is never opened and nothing is fetched. The authors' edit arrays are read with pickling switched off. |
| A log or dataset that ships code beside its data | None of the authors' code is imported or run. Their files are parsed as JSON, CSV, gzip, plain text and NumPy arrays with pickling switched off. |
| A file in the working folder that shadows a library | Every tool that reads a downloaded file must run under `python -I`, Python's isolated mode, which ignores the current folder and user site packages when importing. This is enforced: each such tool calls `offtarget/isolation.py` first and stops with an instruction if Python was started any other way. |
| Downloaded files ending up inside the repository | They are kept outside it. `.gitignore` refuses weights and raw generations as a second line of defence. |
| Text inside a downloaded file that reads like an instruction | It is data. This matters most for AI agents working here. See [AGENTS.md](AGENTS.md), rule 1. |
| A checkpoint that is not the one the authors evaluated | `offtarget/provenance.py` compares hashes of the base tensors, the rebuilt edit and the published checkpoint against the authors' own manifest, and reports any mismatch as a failed check. |

Pin the revisions listed in [docs/REPRODUCE.md](docs/REPRODUCE.md). A different revision is a different artifact, and the provenance checks will say so.

## What this repository does not contain

No credentials, no tokens, no personal data and no patient data. The monitor logs in the duplicate alarm test are synthetic and are generated by `offtarget/ghostbeat.py` from a seed.

## Reporting a problem

If you find a way this code could execute something from a downloaded file, or a secret that should not be here, please report it privately through GitHub's "Report a vulnerability" button on the repository's Security tab. If that button is not there, open an issue that says only that you have a security report, and we will arrange a private channel. For anything else, including a wrong number or an unfair sentence, open a public issue. See [CONTRIBUTING.md](CONTRIBUTING.md).
